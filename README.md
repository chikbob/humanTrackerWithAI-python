# Система мониторинга и интеллектуального анализа входной зоны предприятия

Проект выполнен в рамках темы ВКР:
**"Разработка веб-системы мониторинга и интеллектуального анализа объектов в реальном времени с использованием нейросетевых моделей".**

Прикладная область текущей версии проекта:
**мониторинг и интеллектуальный анализ прохода сотрудников на предприятие**.

Система предназначена для мониторинга входной зоны предприятия. В текущей реализации веб-приложение в реальном времени обнаруживает объекты на видеопотоке, поддерживает детекцию класса `person`, отслеживает перемещение объектов в контролируемой зоне прохода с помощью трекинга, сохраняет события наблюдения и формирует журнал для последующего анализа. Архитектура проекта ориентирована на задачи контроля входа и выхода сотрудников; при этом полноценная интерпретация кадров как подтвержденных бизнес-событий `вход/выход сотрудника` остается направлением дальнейшего развития.

## Цель проекта

Разработать веб-систему, которая позволяет автоматически анализировать видеопоток из входной зоны предприятия, выявлять присутствие людей, отслеживать их перемещение в зоне прохода и накапливать журнал наблюдений для мониторинга и последующего анализа.

## Предметная область

Предметная область проекта связана с контролем прохода сотрудников через входную группу предприятия. Для такой зоны важны непрерывное видеонаблюдение, обнаружение людей в кадре, фиксация их появления в контролируемой области, накопление истории наблюдений и последующая аналитическая обработка событий.

## Решаемая проблема

На проходной предприятия оператору сложно вручную непрерывно отслеживать видеопоток и фиксировать все значимые события. Проект решает задачу автоматизации первичного мониторинга входной зоны:

- обнаруживает людей и другие объекты на кадрах;
- отслеживает перемещение объектов в видеопотоке;
- фиксирует события появления объекта и входа в выделенную зону наблюдения;
- сохраняет историю сеансов, кадров и событий в журнале наблюдений;
- предоставляет интерфейс для просмотра истории, фильтрации и экспорта результатов.

Полноценное разделение событий именно на `вход сотрудника` и `выход сотрудника` в терминах системы контроля доступа пока не реализовано как отдельная завершенная бизнес-функция. Сейчас для этого используются базовые признаки: вход объекта в ROI и исчезновение отслеживаемого объекта.

## Сценарий использования

1. Оператор запускает веб-приложение и выбирает источник данных: камеру, изображение или видеофайл.
2. Система обрабатывает поток с помощью нейросетевой модели YOLO.
3. При обнаружении человека система отображает рамку, класс объекта и уровень уверенности.
4. При работе с видео или камерой система использует трекинг для наблюдения за перемещением объекта в зоне прохода.
5. При попадании человека в контролируемую область формируется событие наблюдения.
6. Журнал наблюдений сохраняется в базе данных и доступен для просмотра в интерфейсе.
7. Оператор анализирует историю сеансов, событий и при необходимости экспортирует отчеты.

## Преимущества для предприятия

- снижение нагрузки на оператора видеонаблюдения;
- ускорение обнаружения событий в зоне прохода;
- накопление цифрового журнала наблюдений по сеансам мониторинга;
- возможность последующего анализа активности во входной зоне;
- основа для дальнейшей интеграции с задачами контроля доступа и учета прохода сотрудников.

## Текущие возможности системы

В коде проекта на текущий момент реализованы следующие функции:

- веб-интерфейс на `Streamlit`;
- обработка изображений, видеофайлов и камер;
- детекция объектов на базе моделей `YOLOv8`;
- трекинг объектов в видео и при работе с локальной камерой;
- выделение и контроль `ROI` для зоны прохода;
- журналирование сеансов, кадров и событий в `SQLite`;
- просмотр событий, уведомлений, базовой аналитики и экспорт отчетов.

С точки зрения прикладной области проходной предприятия это означает, что система уже может использоваться как прототип интеллектуального мониторинга входной зоны: она обнаруживает людей, отслеживает их перемещение в кадре, фиксирует вход в контролируемую область и формирует журнал наблюдений.

## Ограничения текущей версии

- идентификация личности сотрудника не реализована;
- интеграция со СКУД, пропусками или кадровыми системами не реализована;
- отдельные подтвержденные события `вход` и `выход` сотрудника пока не выделяются как завершенная бизнес-логика;
- разграничение сотрудников и посетителей не реализовано;
- отсутствует модуль построения отчетности по рабочему времени и дисциплине прохода.

## Параметры производительности

Для режима реального времени на производительность больше всего влияют:

- `frame_skip` — позволяет пропускать часть кадров и снижать нагрузку на CPU/GPU;
- `inference_size` — уменьшает или увеличивает размер кадра для инференса модели;
- `confidence_threshold` — влияет на число обрабатываемых детекций и объем последующей логики.

Для стабильной работы на слабом оборудовании обычно достаточно уменьшить `inference_size` и увеличить `frame_skip`.

## Перспективы развития

- выделение отдельных бизнес-событий `вход сотрудника` и `выход сотрудника` на основе траекторий и правил пересечения контрольной линии;
- интеграция с системой контроля и управления доступом предприятия;
- распознавание личности сотрудника или сопоставление с пропуском;
- автоматическое разделение сотрудников, посетителей и посторонних лиц;
- формирование отчетов по интенсивности прохода и загруженности входной зоны;
- расширение аналитики для выявления аномалий и нарушений регламента прохода;
- поддержка нескольких камер и единого централизованного журнала наблюдений.

## Запуск проекта

Установить зависимости:

```bash
pip install -r requirements.txt
```

Запустить приложение:

```bash
streamlit run app.py
```

## Структура проекта

- `app.py` — основное веб-приложение мониторинга и аналитики;
- `uapp.py` — упрощенная версия приложения;
- `monitoring.db` — локальная база данных с сеансами и событиями;
- `yolov8n.pt`, `yolov8s.pt`, `yolov8m.pt` — файлы моделей YOLO.
