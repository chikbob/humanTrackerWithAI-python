# Веб-система мониторинга и интеллектуального анализа объектов в реальном времени для входной зоны предприятия

Проект выполнен в рамках темы ВКР:
**"Разработка веб-системы мониторинга и интеллектуального анализа объектов в реальном времени с использованием нейросетевых моделей".**

Прикладная область текущей версии проекта:
**мониторинг и интеллектуальный анализ прохода сотрудников на предприятие**.

Проект представляет собой веб-систему мониторинга и интеллектуального анализа объектов в реальном времени на основе нейросетевых моделей. В прикладном сценарии система ориентирована на мониторинг прохода сотрудников на предприятии: она обрабатывает видеопоток входной зоны, обнаруживает людей и иные объекты, отслеживает их перемещение, фиксирует события наблюдения и формирует журнал для последующего анализа. Архитектура решения ориентирована на задачи контроля прохода сотрудников; при этом полноценная интерпретация кадров как подтвержденных событий `вход/выход сотрудника` остается направлением дальнейшего развития.

## Цель проекта

Разработать веб-систему мониторинга и интеллектуального анализа объектов в реальном времени, которая автоматически обрабатывает видеопоток входной зоны предприятия, выявляет присутствие людей, отслеживает их перемещение в зоне прохода и накапливает журнал наблюдений для последующего анализа.

## Предметная область

Предметная область проекта связана с контролем прохода сотрудников через входную зону предприятия. Для данной области критичны непрерывный мониторинг видеопотока, обнаружение объектов в кадре, фиксация появления людей в контролируемой области, накопление истории наблюдений и последующая аналитическая обработка событий.

## Решаемая проблема

При ручном наблюдении за входной зоной предприятия оператору затруднительно непрерывно контролировать видеопоток и фиксировать все значимые события. Проект решает задачу автоматизации первичного мониторинга и интеллектуального анализа:

- обнаруживает людей и другие объекты на кадрах;
- отслеживает перемещение объектов в видеопотоке;
- фиксирует события появления объекта и входа в выделенную зону наблюдения;
- сохраняет историю сеансов, кадров и событий в журнале наблюдений;
- предоставляет интерфейс для просмотра истории, фильтрации и экспорта результатов.

Полноценное разделение событий именно на `вход сотрудника` и `выход сотрудника` в терминах системы контроля доступа пока не реализовано как отдельная завершенная бизнес-функция. Сейчас для этого используются базовые признаки: вход объекта в ROI и исчезновение отслеживаемого объекта.

## Сценарий использования

1. Оператор запускает веб-приложение и выбирает источник данных: камеру, изображение или видеофайл.
2. Система обрабатывает видеопоток с помощью нейросетевой модели YOLO.
3. При обнаружении человека система отображает рамку, класс объекта и уровень уверенности.
4. При работе с видео или камерой система использует трекинг для наблюдения за перемещением объекта в зоне прохода.
5. При попадании человека в контролируемую область формируется событие наблюдения.
6. Журнал наблюдений сохраняется в базе данных и доступен для просмотра в интерфейсе.
7. Оператор анализирует историю сеансов, событий и при необходимости экспортирует отчеты.

## Преимущества для предприятия

- снижение нагрузки на оператора системы видеомониторинга;
- повышение оперативности обнаружения событий в зоне прохода;
- накопление цифрового журнала наблюдений по сеансам мониторинга;
- возможность последующего интеллектуального анализа активности во входной зоне;
- формирование архитектурной основы для интеграции с задачами контроля доступа и учета прохода сотрудников.

## Текущие возможности системы

В коде проекта на текущий момент реализованы следующие функции:

- веб-интерфейс на `Streamlit`;
- обработка изображений, видеофайлов и камер;
- детекция объектов на базе моделей `YOLOv8`;
- трекинг объектов в видео и при работе с локальной камерой;
- выделение и контроль `ROI` для зоны прохода;
- журналирование сеансов, кадров и событий в `SQLite`;
- просмотр событий, уведомлений, базовой аналитики и экспорт отчетов.

С точки зрения прикладного сценария прохода сотрудников это означает, что система уже может использоваться как прототип веб-системы мониторинга и интеллектуального анализа входной зоны: она обнаруживает людей, отслеживает их перемещение в кадре, фиксирует вход в контролируемую область и формирует журнал наблюдений.

## Ограничения текущей версии

- идентификация личности сотрудника не реализована;
- интеграция со СКУД, пропусками или кадровыми системами не реализована;
- отдельные подтвержденные события `вход` и `выход` сотрудника пока не выделяются как завершенная бизнес-логика;
- разграничение сотрудников и посетителей не реализовано;
- отсутствует модуль построения отчетности по рабочему времени и дисциплине прохода.

## Параметры производительности

Для режима реального времени на производительность больше всего влияют:

- `frame_skip` — позволяет пропускать часть кадров и снижать нагрузку на CPU/GPU;
- `inference_size` — уменьшает или увеличивает размер кадра для инференса модели;
- `confidence_threshold` — влияет на число обрабатываемых детекций и объем последующей логики.

Для стабильной работы на слабом оборудовании обычно достаточно уменьшить `inference_size` и увеличить `frame_skip`.

## Сценарий демонстрации

Рекомендуемый сценарий демонстрации на защите ВКР:

1. Запустить веб-систему командой `streamlit run app.py`.
2. В интерфейсе активировать `Демо-режим защиты ВКР` для использования устойчивых параметров обработки и тестового списка сотрудников.
3. Выбрать источник данных: заранее подготовленное видео входной зоны предприятия или камеру.
4. Показать обнаружение человека в кадре и его попадание в контролируемую входную зону.
5. Продемонстрировать автоматическую фиксацию события в журнале наблюдений и журнале проходов.
6. Перейти в раздел `Журнал событий` и показать зарегистрированные события мониторинга.
7. Перейти в раздел `Статистика проходов` и показать базовые аналитические показатели.
8. При необходимости открыть раздел `Список сотрудников` и показать тестовые записи, подготовленные для демонстрации.

Для демонстрации рекомендуется использовать короткий видеоролик со сценарием появления человека во входной зоне либо локальную камеру с заранее подготовленным ракурсом.

## Перспективы развития

- выделение отдельных бизнес-событий `вход сотрудника` и `выход сотрудника` на основе траекторий и правил пересечения контрольной линии;
- интеграция с системой контроля и управления доступом предприятия;
- распознавание личности сотрудника или сопоставление с пропуском;
- автоматическое разделение сотрудников, посетителей и посторонних лиц;
- формирование отчетов по интенсивности прохода и загруженности входной зоны;
- расширение аналитики для выявления аномалий и нарушений регламента прохода;
- поддержка нескольких камер и единого централизованного журнала наблюдений.

## Запуск проекта

Установить зависимости:

```bash
pip install -r requirements.txt
```

Запустить приложение:

```bash
streamlit run app.py
```

## Структура проекта

- `app.py` — основное веб-приложение мониторинга и интеллектуального анализа;
- `core/`, `services/`, `db/`, `ui/`, `utils/` — модули прикладной логики, интерфейса, хранения данных и вспомогательных функций;
- `monitoring.db` — локальная база данных с сеансами и событиями;
- `yolov8n.pt`, `yolov8s.pt`, `yolov8m.pt` — файлы моделей YOLO.
